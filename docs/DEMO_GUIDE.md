# Minibrain 面试演示与准备手册

目标不是把所有页面都点一遍，而是在 5 分钟内证明三件事：项目真的能运行；架构选择有原因；结论来自实验而不是堆名词。

## 1. 面试前准备清单

演示前一天：

- 用 Docker Compose 或本地 PostgreSQL 完整启动 Web、Worker 和数据库；
- 创建一个普通用户和一个管理员，准备一份私有文档、一份公共文档；
- 预先上传一份 Markdown/PDF 和一份 XLSX，确认状态均为 `ready`；
- 预跑 4 个演示问题，把稳定结果和运行记录留在数据库；
- 打开“知识库、问答、检索实验室、运行记录、指标”五个页面；
- 保存一张架构图和关键评测表的本地截图，网络或模型接口失败时仍可讲；
- 关闭无关窗口和敏感配置，浏览器字号调大；
- 不在现场重新安装依赖、重新构建全量索引或跑付费全量评测。

建议准备的四类问题：

1. 文档事实题：能展示引用和页码/标题路径；
2. 精确编号题：能展示 BM25 如何救回 Dense 不擅长的编号；
3. 表格聚合题：能展示为什么 SQL 不能被向量检索替代；
4. 无答案题：能展示系统拒答和安全门。

## 2. 两分钟项目介绍稿

可以直接按下面的结构说，不需要逐字背：

> Minibrain 是我做的一个企业知识库 Agentic RAG 原型。它不是把所有数据都塞进向量库，而是分成两条数据链路：非结构化文档走 pgvector 和 BM25 的 RRF 混合检索，CSV/XLSX 走受限只读 SQL，因为聚合计算不能靠召回片段猜。
>
> 文档入库是可恢复异步任务，支持 Markdown、HTML、DOCX、PPTX、带文字层 PDF；切分采用 800 字 child 和 1600 字 parent。实验发现真正有收益的是 parent-aware 去重，而不是把完整 parent 塞进上下文，所以默认只开启去重。
>
> 问答层用 LangGraph 做工具路由和多跳检索，PostgreSQL 保存会话，并用数据库锁和 request ID 解决同会话并发与重试幂等。权限始终在检索 SQL 里过滤，缓存也绑定用户和知识版本。
>
> 最终答案是结构化 claims，每个事实绑定证据编号。服务端会确定性检查引用、数字和业务编号；失败就安全拒答。SSE 只发布校验后的最终答案。
>
> 我还做了自造企业集、NanoNQ/NanoHotpotQA 公开集、端到端 Judge 和 CI 回归门禁。MMR、cross-encoder、HyDE、GraphRAG 都做过实验，但没有因为流行就放进默认链路。这套项目最想展示的是：我能实现 RAG，也能通过实验知道什么不该用。

## 3. 五分钟现场演示脚本

### 0:00–0:40：先讲架构，不先点页面

打开 [`ARCHITECTURE.md`](ARCHITECTURE.md) 的系统全景图，只讲两条主链路和最后的安全门。强调 GraphRAG、手写版都是实验角色，不要让面试官误以为有三套重复产品。

### 0:40–1:30：展示知识入库

打开知识库页：

- 指出文档和表格自动分流；
- 展示一个 PDF 的 `page-aware` 或 PPTX 的 `slide-aware` 解析状态；
- 解释 Web 只登记，Worker 异步入库，失败会进入 `failed/dead_letter`；
- 如果时间允许，重复上传同一文件，说明 hash 复用和版本更新。

不要现场上传大文件等待 embedding。预先准备 ready 数据，现场只展示状态和机制。

### 1:30–2:30：展示混合检索

在检索实验室输入一个带会议号、工单号或项目号的问题：

- Dense 能理解语义，但相似文档分数可能很接近；
- BM25 对精确编号命中明显；
- RRF 按排名融合；
- 确定性去重避免同一 parent 的多个 child 挤满 top-k；
- MMR/CE 按钮存在，但默认关闭，并简述对应消融结论。

这一段是证明“架构图上的每个方框真的运行了”。

### 2:30–3:20：展示表格 SQL

问一个“合计、分组或筛选”问题。展示 Agent 选择 `table_query`，结果来自数据库而不是向量片段。补一句四层 SQL 护栏：表名白名单、只允许 SELECT/WITH、强制 LIMIT、只读事务与超时。

### 3:20–4:10：展示引用与拒答

先问一个有答案的文档题，指出答案 claim、证据编号和原文位置。再问一个知识库里不存在的精确编号，展示系统不会因为向量库总能返回最近邻就强答。

强调没有额外的 LLM evidence selector：最终生成模型直接使用检索证据，生成后用确定性规则检查引用。

### 4:10–5:00：用数字收尾

打开运行记录或评测报告，只选三条讲：

- parent-aware 去重：Recall@5 0.847→0.886，token 不增加；
- cross-encoder：排序变好，但 P50 约 14ms→1467ms且 context 变长，因此默认关闭；
- no-answer 分数阈值：held-out 误拒 26.7%、无答案召回 0%，因此否决硬阈值。

最后主动给边界：只有本机 20 并发的小压测，没有生产规模证据；OCR/复杂 PDF 版面、外部知识源连接器和完整 DLP 也尚未覆盖。

## 4. 备用的 10 分钟技术讲解

如果面试官让你展开，按这个顺序，不要按代码目录讲：

1. 为什么文档和表格必须分两条链路；
2. ingestion 的格式识别、异步任务、版本与索引一致性；
3. Dense/BM25 的互补、RRF、metadata、去重和 token budget；
4. Agent 多跳、会话持久化、并发锁和幂等；
5. claims、引用安全门和无答案策略；
6. 离线评测、在线反馈、Trace 与 CI 回归；
7. 三个被实验否决的方案；
8. 生产化边界和下一步扩展。

每一段都使用同一种答题模板：先给结论，再讲项目实现，再给实验或故障证据，最后说边界。

## 5. 最值得准备的五个项目故事

### 故事一：混合检索不是“多路更保险”

- 问题：Dense 对只差编号的会议纪要区分度很低。
- 证据：8 篇相似纪要余弦分数挤在 0.60–0.67，MRR 只有 0.489；BM25 对编号一击即中。
- 决策：Dense 与 BM25 独立召回，RRF 融合。
- 边界：NanoNQ 上纯向量反而最好，因此 hybrid 不是永远提升。

### 故事二：父子检索的收益被拆开了

- 问题：通常会把 small-to-big 当成一个整体功能。
- 实验：flat child、parent-aware 去重、完整 parent 展开三组对照。
- 结果：去重带来 Recall@5 0.847→0.886；展开 parent 增加 469 token，却没有提高答案支持。
- 决策：默认只去重，完整展开保留为关闭的实验开关。

### 故事三：rerank 排得更准，不等于系统更好

- 结果：cross-encoder 提高 Complete Recall@5 和 NDCG，但 P50 增加约 1.45 秒，context 反而更长。
- 决策：实验室保留，产品默认关闭。
- 方法：优化必须同时比较质量、延迟和上下文成本，不能只看单个排序指标。

### 故事四：最近邻分数不能判断有没有答案

- 做法：用 58 道可答题和 8 道无答案题做固定 held-out 校准。
- 结果：阈值在验证集误拒 4/15，可答题误拒率 26.7%，无答案召回仍为 0%。
- 决策：分数只观测；仅空结果和精确编号不存在提前拒答，其他情况交给 claim 级安全门。

### 故事五：指标也会骗你

- 问题：HNSW 实验曾把索引膨胀导致的退化误认为近似检索的正常召回损失。
- 发现：重复实验无法复现，检查 `EXPLAIN` 和索引大小后才定位。
- 规则：结论至少可复现两次；既要怀疑反直觉结果，也要怀疑“正好符合理论”的结果。

## 6. 演示失败时怎么处理

- 模型 API 超时：打开已保存的 Run Trace，按证据、claims 和阶段耗时复盘；不要反复点击制造更多并发请求。
- Worker 未处理：展示任务状态和 lease 设计，再使用已经 ready 的数据继续。
- 网络断开：使用本地架构文档、评测报告和预存截图完成讲解。
- 回答有波动：不要藏。先判断目标文档是否召回；召回了却答错是生成问题，没召回是检索问题，现场使用检索实验室定位。
- 遇到没做的功能：明确说当前边界和生产方案，不要临场声称已经实现。

## 8. 面试结束前的项目总结

> 这个项目目前已经是完整的面试型 RAG 项目：有多源入库、两类检索范式、Agentic 多跳、权限、引用安全、异步任务、可观测和评测闭环。我补了两模型 Embedding 对比和本机 20 并发压测；它离真正生产系统的差距主要是持续规模压测、复杂文档解析、外部连接器和企业数据治理。下一步优先补真人盲标和公开集上的模型迁移回归，而不是继续堆功能。
