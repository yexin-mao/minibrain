# Minibrain 面试演示视频脚本

目标成片：5～7 分钟，1920×1080，30 FPS。采用真实页面分段录制，后期配音。
LLM Wiki 只在开场提一句，最后作为 MVP 展开。

## 素材文件

将原始录屏放到 `output/demo/input/`，按下面名称保存：

```text
01-home.mov
02-ingestion.mov
03-retrieval.mov
04-vector-rag.mov
05-table-rag.mov
06-multitool.mov
07-observability.mov
08-wiki.mov
```

录制前点击“加载示例知识”，等待三篇文档和一张表全部变成 `ready`，并提前为
“示例-差旅报销制度.md”生成 Wiki。

## 01｜首页与定位（0:00–0:35）

操作：从首页顶部缓慢移动到问答区，不输入问题。

旁白：

> Minibrain 是一个企业知识库 Agentic RAG 原型。非结构化文档走 Dense 和 BM25 的
> RRF 混合检索，CSV 和 XLSX 走受限只读 SQL，再由 LangGraph 根据问题选择工具并完成
> 多跳查询。系统还包含异步入库、权限过滤、引用校验、运行监控和评测闭环。最后我还
> 实现了一个 LLM Wiki MVP，作为知识组织方式的轻量探索。

## 02｜异步入库（0:35–1:15）

操作：展示“添加知识”“知识源管理”、文档表和表格表；鼠标依次停在解析方式、版本、
source、状态和片段数。不要现场上传文件。

旁白：

> 上传时 Web 只校验文件并登记任务，后台 Worker 使用 lease 领取并持续续租。文档经过
> 内容格式识别、结构解析、八百字 child 和一千六百字 parent 切分，再写入 pgvector 和
> 持久化 BM25。CSV 和 XLSX 不切块，而是建立隔离的物理表。临时错误会重试，耗尽后进入
> dead-letter，页面支持人工重试。

## 03｜混合检索实验室（1:15–2:05）

操作：进入“检索实验室”，输入：

```text
P0 故障要求多长时间响应，恢复后什么时候完成复盘？
```

结果出现后，从 Dense、BM25、RRF 移动到 Parent 去重和最终证据。

旁白：

> 检索实验室直接运行正式检索链路，但不调用生成模型。Dense 负责语义表达，BM25 对
> P0 这类编号和精确关键词更敏感。两路分数量纲不同，因此使用 RRF 融合排名。最终再按
> parent id 去重，避免同一段落的多个 child 挤满 Top-K。完整 parent 展开默认关闭，因为
> 实验中增加了上下文 Token，却没有提高答案支持率。

## 04｜Vector RAG 与引用安全（2:05–2:55）

操作：回到首页，输入：

```text
二线城市住宿一晚最多能报多少钱？超标后怎么办？
```

剪掉大部分等待，只保留约两秒处理状态。展开工具轨迹与证据。

旁白：

> Agent 判断这是制度事实题，因此调用 vector_search。检索结果会转换成带编号的
> Evidence，模型输出 answer 和原子 claims，每个事实都必须绑定 evidence id。服务端还会
> 检查引用是否存在，以及 claim 中的数字和业务编号是否出现在对应证据中。校验通过后，
> SSE 才发布最终答案；失败则安全拒答。

## 05｜Table RAG（2:55–3:35）

操作：点击“新对话”，输入：

```text
华东区的销售额合计是多少？
```

展示答案 `206000 元`、`table_query` 和 SQL 证据。

旁白：

> 聚合问题由 Agent 路由到 Table RAG，结果是数据库计算出的二十万六千元，不让模型根据
> 部分片段猜测。SQL 执行前会检查当前用户可见的表名白名单，只允许一条 SELECT 或 WITH，
> 外层强制 LIMIT，并使用只读事务和执行超时。

## 06｜多工具问题（3:35–4:15）

操作：点击“新对话”，输入：

```text
华东区销售额合计是多少？二线城市住宿上限又是多少？
```

展示两个工具的轨迹和两类证据。

旁白：

> 这个问题同时需要结构化表格和制度文档。Agent 调用 table_query 计算销售额，再调用
> vector_search 查询住宿标准，最后将 SQL 证据和文档引用合并。这是项目中 Agentic RAG
> 的主要价值：根据缺失信息选择不同工具，而不是固定执行一次向量检索。

## 07｜Run Trace 与监控（4:15–5:00）

操作：打开“运行记录”，进入刚才的运行详情；依次展示工具调用、Evidence、Claims、延迟
和 Token。随后打开“监控指标”。

旁白：

> 每次问答保存 request id、session id、工具轨迹、证据、claims、延迟、Token、模型版本和
> 稳定错误码，但不保存模型内部推理。request id 用于重试幂等，session id 用于多轮会话。
> 监控页聚合成功率、无证据率、P50 和 P95、引用覆盖以及用户反馈。差评还可以导出为待
> 人工审核的回归候选。

## 08｜LLM Wiki MVP（5:00–5:50）

操作：进入“知识 Wiki”，打开提前生成的差旅制度页面，停留在 source、filename 和版本；
返回后输入：

```text
出差住宿和交通分别怎么报销？
```

展示 Wiki 回答和 `[W1]` 引用。

旁白：

> 前面是正式 RAG 主链路。这里是一个独立的 LLM Wiki MVP：每篇 ready 文档保留一篇可追溯
> 的来源摘要，同时最多新建或更新三个主题页。主题可以由多篇原文共同支持，并保留来源版本
> 和显式关联。Wiki 问答不会调用原文 Vector RAG，而是在当前用户可见、版本最新的来源页和
> 主题页中执行 BM25，取 Top 3 后生成带 W 编号引用的答案。原文更新会让受影响页面失效；
> 首页还会确定性检查过期来源、无来源主题和孤立主题。它仍是 MVP，尚不做实体图谱和语义
> 矛盾裁决。

## 09｜评测结尾（5:50–6:20）

画面：停留在监控页或项目首页，不再操作。

旁白：

> 项目中的技术选择由实验决定。Parent-aware 去重让 Recall@5 从零点八四七提高到零点八八六；
> Cross-encoder 虽然改善排序，却把检索 P50 从约十四毫秒提高到一千四百六十七毫秒，所以
> 默认关闭；相似度硬阈值又会误拒百分之二十六点七的可回答问题，因此只用于观测。这个项目
> 想展示的不是堆 RAG 名词，而是把入库、检索、生成安全和评测做成完整闭环。

## 录制要求

- 每段开头和结尾保留两秒静止画面。
- 点击后停顿一秒，方便后期加框和放大。
- 模型等待可以完整录下，后期统一删除。
- 不录登录密码、`.env`、API Key 或包含个人信息的浏览器区域。
- 不使用背景音乐；最终配真人旁白和中文字幕。
