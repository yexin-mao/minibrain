# 端到端回答质量 smoke

日期：2026-08-17

## 实验范围

- 语料：130 篇文档 + 3 张表
- 用例：8 题 smoke（4 道幻觉/拒答、2 道正常对照、2 道多跳）
- 回答模型：`deepseek/deepseek-v4-flash`
- Judge：同一个模型，结构化逐 claim 判定
- Judge v3 人工校准：4/4 通过
- 原始结果：`answer-quality-after-stop-fix.json`
- v3 重判结果：`answer-quality-rejudged.json`

这不是完整 33 题结论，也不是独立 Judge 结论。小数用于定位问题，不能当成模型能力的绝对真值。

## 评测先抓出了一处产品故障

第一次运行只有销售聚合题成功，另外 7/8 全部触发 `GraphRecursionError`。根因不是 Judge：
手写 Agent 在达到工具轮数上限后会移除工具并强制基于已有证据作答，但迁移到 LangGraph 时
这段兜底没有迁过去，只剩裸 `recursion_limit`。

修复后保留最后图状态和已取得证据，达到上限时使用一次**无业务检索工具**的结构化调用收口。
这不是 evidence selector，也不改变正常路径；只在原本会直接报错的耗尽路径触发。

| | 修复前 | 修复后 |
|---|---:|---:|
| 成功完成 | 1/8 | **8/8** |
| 递归上限错误 | 7/8 | **0/8** |

## 最重要的测量发现

`mh-01` 的旧子串检查是 `true`，因为回答里出现了“技术部”；但完整原句是
“无法确定负责人所属部门（如技术部、研发中心等）”。词出现了，语义却是否定的，
Judge 因此判 0。这个样例实证了：**子串匹配会把否定语境判成正确答案。**

Citation v1 曾把正确拒答中的“资料没有该项目”按空引用罚 0。v3 将这类信息缺失元声明标成
`not_applicable`，同时从 Faithfulness 和 Citation Correctness 分母排除。校准样例也改为原子 claim，
避免把“一半支持、一半编造”的复合句到底算 partial 还是 unsupported 变成措辞游戏。

## 当前结论

系统现在能稳定收口，拒答和语义忠实度较好，但两道多跳都没有给出完整正确答案；
主要缺口已经从“会报错”变成“续查策略和长文档正文召回不足”。同时，同模型自评仍有偏差风险，
正式对外结论需要独立 Judge 加人工抽样复核。

## 2026-08-18 定向修复回归

这不是重跑整套 smoke，而是只重跑两个原失败样本；原始明细分别是
`answer-quality-multihop-fix-mh01.json`、`answer-quality-longdoc-fix-mh08.json` 和
`answer-quality-longdoc-scope-fix-mh08.json`。

- `mh-01`：真实轨迹走完 `项目 → 算法组 → 技术部`，没有强制收口；Correctness、
  Faithfulness、Citation、Relevance 均为 **1.0**，生成耗时 10.1 秒。
- `mh-08`：修复后已经召回 `policy-supplier.md` 中的“采购比价 + 天元法务审核”，并实际
  触发带 `filename=long-handbook-采购.md` 的文档内检索。两次生成的 Correctness 分别为
  **0.7 / 0.5**，但 Faithfulness 与 Citation 均为 **1.0**。扣分来自模型把“每年复审”
  和“完整尽调流程不足”扩写进答案，不是目标证据缺失。

因此这里停止继续调 prompt：检索缺口已经闭合，但生成简洁性仍有模型波动。为了把单题
刷到 1.0 继续加词会造成测试集过拟合；下一次应在完整集或独立 Judge 上验证，而不是只重跑
`mh-08`。
