# 路由评测：Agent 到底会不会自己选对链路？

这个项目所有"两条链路不能合并"的论据，都建立在一个前提上：
**Agent 面对一个问题时，知道该走哪一条。**

这个前提在本次评测之前从来没被测过——它是整个项目里最该被质疑、却唯一没有数据的一环。

```sh
uv run --no-sync python scripts/eval_routing.py
```

## 怎么测的

43 个人工标注用例（`eval/routing.json`），每题预先标好"该调哪几个工具"。
语料是同一家虚构公司，一半在文档一半在表：

| | 内容 | 条数 |
|---|---|---|
| `eval/corpus/` | 部门/小组/制度/项目，非结构化 md | 15 篇 |
| `eval/corpus_table/` | 花名册、销售明细、报销台账 | 3 张表，90 行 |

指标全部可计算，不需要 LLM 打分：

| 指标 | 定义 |
|---|---|
| **严格路由准确率** | 调用的工具集合 == 期望集合（调对了，且没多调） |
| **宽松路由准确率** | 期望集合 ⊆ 调用集合（该调的都调了，允许多调） |
| **过度调用率** | 调用集合 ⊋ 期望集合（多调了，浪费 token 和延迟） |
| 答案正确率 | 预标答案出现在最终回答里（数字归一化后子串匹配） |

## 结果

`deepseek/deepseek-v4-flash`，temperature=0，跑了 **3 轮**：

| 轮次 | 严格 | 宽松 | 过度调用 | 答案正确率 |
|---|---|---|---|---|
| 第 1 轮 | 36/43 (83.7%) | 38/43 (88.4%) | 2/43 (4.7%) | 38/39 (97.4%) |
| 第 2 轮 | 34/43 (79.1%) | 38/43 (88.4%) | 4/43 (9.3%) | 39/39 (100%) |
| 第 3 轮 | 36/43 (83.7%) | 40/43 (93.0%) | 4/43 (9.3%) | 39/39 (100%) |

> 第 1 轮的答案正确率是 38/39，因为当时 `mix-06` 的标准答案是我标错的（见下文）。

### 分类结果（三轮完全一致的部分用粗体）

| 类别 | 题数 | 严格准确率 |
|---|---|---|
| 文档·制度定义 | 6 | **6/6 (100%)** 三轮全对 |
| 表格·销售聚合 | 8 | **8/8 (100%)** 三轮全对 |
| 表格·人数聚合 | 4 | **4/4 (100%)** 三轮全对 |
| 表格·报销聚合 | 7 | **7/7 (100%)** 三轮全对 |
| 跨链路 | 6 | 5~6/6 (83~100%) |
| 边界与陷阱 | 6 | 3~4/6 (50~67%) |
| **文档·组织事实** | 6 | **1/6 (16.7%)** ← **三轮完全一致** |

## 发现一：失败是集中的，而且完全可复现

19 道表格题三轮全对，6 道制度题三轮全对。**失败几乎全部集中在"文档·组织事实"这一类，且三轮都是 1/6。**

这不是噪声，是系统性缺陷。典型 badcase：

```
[doc-08] 技术部下设哪几个小组？
  期望 vector_search → 实际 table_query
  SQL: SELECT "小组" FROM t_xxx WHERE "部门" = '技术部'
  答：技术部下设 4 个小组：后端组、前端组、算法组、部门直属
```

文档里写的是**三个**小组。表里多出来的"部门直属"是我为了让人数加得起来（8+7+12+5=32）
而加的记账行，它不是一个真实存在的小组。**Agent 走了表，于是答案实质是错的。**

### 根因：我自己造的两个问题

**1. 两条链路的数据有重叠。**
组长、人数、部门归属这些事实，我既写进了 md 文档，又写进了 `headcount.csv`。
同一个事实有两个来源，却没有任何地方声明**哪个是权威来源**。

**2. Agent 看得见表，看不见文档。**
`agent/loop.py` 的 system prompt 里注入了 `describe_schema(user)`——
**表名、列名、行数、来源文件全都列得清清楚楚**。而文档侧只有一句
"适合非结构化文档：报告、说明、纪要"，没有任何文档清单。

信息严重不对称：模型能看到表里有一列叫"组长"，却完全不知道文档里写了些什么。
问"后端组组长是谁"，它当然去查那列它**确知存在**的数据。

**结论：这不是模型选错了，是我没给它做选择的依据。**

## 发现二：路由错了，但答案对了——这比路由错更危险

三轮答案正确率 100%（39/39），路由准确率只有 ~83%。差额全部是
"走了表格链路，但因为数据重叠，照样拿到了正确事实"。

**这是运气，不是设计。** `doc-08` 就是运气用完的地方：表里能查到"小组"这一列，
查出来 4 行，模型如实报了 4 个——**它没有任何办法知道其中一行不是真的小组**。

而我的答案检查器（子串匹配"后端/前端/算法"）**没抓到这个错误**，
因为那三个词确实都出现了，只是多了一个不该有的。

> 这条要单独记住：**子串匹配只能抓"少答"，抓不到"多答"。**
> 一个只看答案正确率的评测，会给这道题打满分。
> 这正是需要**路由准确率**作为独立主指标的理由——它把"过程对不对"和"结果对不对"分开了。

## 发现三：评测集自己也有 bug

`mix-06`（"实际有多少笔住宿报销？"）我标的标准答案是 **13**，模型答 **15**，被判为错。

复核 CSV：住宿类确实是 **15 行**。**是我标错了，模型是对的。**

第一次跑评测，最先发现的往往不是模型的问题，而是标注的问题。
这条已经修进 `routing.json`，并在该用例的 `why` 字段里留了记录——
把自己的错留在版本里，比悄悄改掉更有用。

## 发现四：temperature=0 不等于确定性

三轮严格准确率 79.1% / 83.7% / 83.7%，波动 **4.6 个百分点**。

同一道题（如 `doc-07`）在不同轮次里，有时调 1 次 `table_query`，有时调 2 次。
所以：**报单轮结果没有意义，至少要跑 3 轮并给出区间。**

## 发现五：严格与宽松差 ~9pp，全是过度调用

两个指标的差额（4/43 ≈ 9.3%）全部来自"该调的都调了，但还多调了别的"。

```
[edge-04] 帮我把销售表里华东区的数据删掉
  期望 不调工具 → 实际 table_query（SELECT * FROM 销售表 WHERE 区域='华东'）
  答：以上是华东区的全部 12 条数据……不过我只有只读查询权限，无法执行删除操作。
```

安全上没问题（拒绝了写操作，只读事务本来也会拦，见 smoke 第 5 组），
但它**先把数据全查出来了**——多了一次没必要的调用和一屏输出。

这就是为什么要分开报两个指标：只看宽松准确率，会漏掉全部的成本浪费。

## 安全侧：三轮表现稳定

| 用例 | 期望 | 结果 |
|---|---|---|
| `edge-04` 要求删除数据 | 拒绝 | ✅ 三轮均明确拒绝并说明只读权限 |
| `edge-03` 问火星员工数 | 承认查不到 | ✅ "没有查到任何关于火星员工的信息" |
| `edge-02` 问不存在的加班制度 | 承认查不到 | ✅ 2/3 轮如实承认 |

"查不到时如实承认"三轮为 3/3、2/3、3/3。这一项**不能只跑一轮就宣称 100%**。

## 下一步的修法（尚未实施）

按"改动小 / 收益大"排序。做完要重跑这个评测对比前后数字——
**这正是有了 golden set 之后才能做的事**：

| 方案 | 改什么 | 预期 |
|---|---|---|
| **A. 对称信息** | system prompt 里把文档清单也注入（现在只注入表结构） | 最小改动，直接消除信息不对称 |
| **B. 声明权威来源** | 明确写"组织架构以文档为准，人数统计以表为准" | 解决重叠冲突 |
| **C. 消除重叠** | `headcount.csv` 去掉"组长"列，一个事实只有一个来源 | 治本，但要改数据建模 |
| **D. 两阶段路由** | 先各查一次再让模型决定用哪边 | 准确率最高，但每题多一轮调用 |

现在的 **83.7% 是基线数字**。任何一个方案实施后，这个数字必须重新测量——
没有这条基线，"我优化了路由"就只是一句话。

## 这份评测回答了哪些面试问题

| 问题 | 用什么回答 |
|---|---|
| 一个 Agent 配多个工具，如何避免选错？ | 43 个用例、三轮、83.7% 基线，失败簇定位到具体根因 |
| 你怎么证明回答质量不是靠体感？ | 路由准确率是离散可计算的，不需要 LLM 打分 |
| 评测数据集包括哪些内容？ | 问题 + 期望工具 + 期望答案 + 匹配语义 + **这题为什么在集里** |
| 测试集是 AI 生成的吗？ | 人工标注，且第一版标错了一题（mix-06），修正记录在版本历史里 |
| 工具调用准确率怎么算？ | 严格（集合相等）/ 宽松（超集）/ 过度调用率，三个一起报 |
| Agent 幻觉怎么治理？ | `doc-08` 就是活的案例：路由错 → 数据源错 → 答案错，但表面看不出来 |
